DESIGN DOCUMENT: tpt-formal (FORMAL VERIFICATION FOUNDATION)

BEFORE YOU WRITE ANYTHING BELOW: check tpt-rust-map/registry.toml (in the
sibling tpt-rust-map repo) for an existing foundation or external crate
before adding a new one here. Every crate name in this repo carries the
tpt-for- prefix. A crate is only a valid wrap target if its CURRENT
license is MIT OR Apache-2.0 (or more permissive) — Apache-2.0-ONLY is
always disqualifying, no exceptions (see tpt-rust-map/docs/adr/0007). If
it passes that check, default to wrapping; reimplementation still needs
one written reason. Prefer many small crates + a thin umbrella crate over
one broad crate. Every crate: license = "MIT OR Apache-2.0".

PROJECT OVERVIEW
tpt-formal consolidates tpt-solutions' formal-verification and design-by-
contract primitives — currently spread across tpt-zero-formal (~16
contract/type-safety crates) and tpt-formal-lab (~8 verification crates) —
into one dedicated repo. This pillar was added after the audit turned up a
substantial, distinct body of work in this space that deserved the same
treatment as Math/Science/Engineering, not a fold-in. Every safety-critical
vertical in tpt-solutions (tpt-flight-control, tpt-dynamo, tpt-vanguard,
tpt-chassis, tpt-servo, tpt-relay, and others) is a plausible future
consumer of these primitives.

ECOSYSTEM GAP JUSTIFICATION
Design-by-contract, refinement types, type-level safety encoding, and
deterministic verification tooling are not well served by mature, broadly-
adopted permissive crates in the Rust ecosystem the way linear algebra or
statistics are — this is largely genuine build territory, not wrap
territory. Where an external crate does exist for a piece of this (e.g. an
SMT solver binding for tpt-for-smt-lite's bridge), prefer wrapping it; the
crate-level detail for that call is deferred to implementation time.
tpt-formal-lab's tpt-exact-math does NOT live here — it moved to tpt-math
as tpt-math-exact, since exact/interval arithmetic is a numeric primitive
useful far beyond formal verification.

CORE PRINCIPLES
The grouping below consolidates ~24 legacy crates into 13, merging facets
that are genuinely inseparable (a contract system needs pre/post/invariant
together to be coherent; type-level safety encoding techniques like
phantom/ghost/newtype/bounded are facets of one toolkit) while keeping
everything else at its existing one-crate-one-technique granularity. This
grouping is a judgment call, not derived from audit evidence the way
Math's tpt-math-prob-* split was — see docs/adr/0006 in tpt-rust-map. Split
further, per-crate, the moment a grouped facet wants independent
versioning sooner than expected; don't force a merge a real consumer is
fighting. Dual-licensed MIT OR Apache-2.0. no_std where the underlying
legacy crate was already no_std (marked per crate below) — most of this
pillar's contract/type-safety primitives are no_std by nature since they're
meant to be usable in the embedded/safety-critical verticals that motivate
this pillar.

CRATE INVENTORY

  tpt-for-contract
    Build: consolidates precond/postcond/invariant/loop-inv — tightly
    coupled facets of one design-by-contract concern. no_std. Consolidates
    tpt-zero-formal's tpt-zero-precond, tpt-zero-postcond,
    tpt-zero-invariant, tpt-zero-loop-inv. Depends on: tpt-math-numeric.

  tpt-for-refinement
    Build: refinement types. no_std. Consolidates tpt-zero-formal's
    tpt-zero-refinement. Depends on: tpt-for-contract.

  tpt-for-typestate
    Build: consolidates type-level/phantom/ghost/newtype/bounded/safe-cast
    — one coherent "type-level safety encoding" toolkit. no_std.
    Consolidates tpt-zero-formal's tpt-zero-type-level, tpt-zero-phantom,
    tpt-zero-ghost, tpt-zero-newtype, tpt-zero-bounded, tpt-zero-safe-cast.

  tpt-for-witness
    Build: witness types. no_std. Consolidates tpt-zero-formal's
    tpt-zero-witness. Depends on: tpt-for-typestate.

  tpt-for-assert-const
    Build: compile-time assertions. no_std. Consolidates tpt-zero-formal's
    tpt-zero-assert-const.

  tpt-for-smt-lite
    Build: lightweight SMT bridge. Consolidates tpt-zero-formal's
    tpt-zero-smt-lite and tpt-formal-lab's out-smt-bridge. Check for an
    existing Rust SMT-solver binding to wrap before building the bridge
    logic from scratch — deferred to implementation time, not decided here.

  tpt-for-verified-ode
    Build: verified ODE solving, pairs with tpt-science's tpt-sci-ode.
    Consolidates tpt-formal-lab's tpt-verified-ode. Depends on:
    tpt-sci-ode (from the tpt-science repo), tpt-for-contract.

  tpt-for-verified-algorithms
    Build: verified algorithm implementations. Consolidates
    tpt-formal-lab's tpt-verified-algorithms. Depends on: tpt-for-contract.

  tpt-for-proof-ast
    Build: proof AST representation. Consolidates tpt-formal-lab's
    tpt-proof-ast.

  tpt-for-det-proptest
    Build: deterministic property-based testing. Consolidates
    tpt-formal-lab's tpt-det-proptest.

  tpt-for-deterministic-sim
    Build: deterministic simulation harness. Consolidates tpt-formal-lab's
    tpt-deterministic-sim.

  tpt-for-redundancy
    Build: redundancy/fault-tolerance primitives. no_std. Consolidates
    tpt-formal-lab's tpt-redundancy.

  tpt-for-trace-macros
    Build: trace/instrumentation macros for verification. no_std.
    Consolidates tpt-formal-lab's tpt-trace-macros.

GROUPING CAVEAT
This 13-crate split is provisional (see tpt-rust-map/docs/adr/0006). If,
during implementation, tpt-for-refinement or tpt-for-witness turn out to
need independent release cadence sooner than expected, split them out of
tpt-for-contract/tpt-for-typestate respectively rather than forcing the
merge.

REPO CONVENTIONS
Cargo workspace under crates/, one crate per directory, seeded from
tpt-rust-map/template/. Every crate registered in tpt-rust-map/registry.toml
before implementation starts.
